Subtask 2-2: Add error handling for push failures
------------------------------------------------
Status: COMPLETED

Changes Made to /Applications/Auto-Claude.app/Contents/Resources/backend/agents/tools_pkg/tools/qa.py:

1. Fixed error_type capture:
   - Changed: push_success, push_msg = _push_branch_to_remote(...)
   - To:      push_success, push_msg, error_type = _push_branch_to_remote(...)

2. Enhanced branch_pushed schema in implementation_plan.json:
   - Added error_type: "network" | "timeout" | "auth" | "rejected" | "config" | "unknown" | None
   - Added can_retry: bool - True for retryable errors (network, timeout)
   - Added retry_count: int - Number of retry attempts made

3. Added retry mechanism via new MCP tool:
   - Tool: retry_branch_push
   - Description: Retry a failed branch push operation
   - Only works when status is "push_failed" and can_retry is True
   - Updates retry_count on each attempt
   - Provides clear guidance for non-retryable errors

4. Improved error handling for edge cases:
   - No branch name found: status = "push_failed", error_type = "config", can_retry = False
   - No worktree found: status = "push_failed", error_type = "config", can_retry = False
   - Network/timeout errors: can_retry = True (user can retry with retry_branch_push)
   - Auth/rejected errors: can_retry = False (requires manual intervention)

5. Error type classification:
   - "network": Connection/DNS issues → retryable
   - "timeout": Push timed out (>120s) → retryable
   - "auth": Authentication/permission denied → not retryable (run gh auth login)
   - "rejected": Remote has conflicting changes → not retryable (resolve conflicts)
   - "config": Missing worktree/branch → not retryable (check configuration)
   - "unknown": Unclassified errors → not retryable (manual investigation)

Verification:
- Python syntax check: PASSED (python3 -m py_compile qa.py)
- Manual verification: Test with network disconnected - verify graceful failure and status update

Implementation Notes:
- Retryable errors (network, timeout) can be resolved by fixing connectivity and calling retry_branch_push
- Non-retryable errors provide clear guidance messages for manual resolution
- Status never proceeds to PR creation (or human_review) when push fails
- retry_count tracks cumulative attempts for monitoring

Subtask 3-1: Check for existing PR on branch before creating new one
-------------------------------------------------------------------
Status: COMPLETED

Changes Made to /Applications/Auto-Claude.app/Contents/Resources/backend/agents/tools_pkg/tools/qa.py:

1. Added _check_existing_pr function (lines 187-259):
   - Executes: gh pr list --head <branch> --json url,number,title
   - Returns tuple: (found: bool, pr_info: dict | None, error_message: str)
   - Timeout handling: PR_CHECK_TIMEOUT_SECONDS = 30
   - Error handling for:
     - GitHub CLI not authenticated
     - GitHub CLI not installed (FileNotFoundError)
     - Network timeouts
     - JSON parsing errors

2. Added PR_CHECK_TIMEOUT_SECONDS constant (line 25):
   - 30 seconds timeout for PR list check
   - Prevents hanging on network issues

3. Integrated _check_existing_pr into update_qa_status workflow (lines 424-451):
   - After successful branch push, checks for existing PR
   - If existing PR found:
     - Stores PR details in pr_created object with existing=True flag
     - pr_created: { url, number, title, branch, created_at, existing: True }
     - Transitions directly to human_review
     - Message: "Existing PR found: #<number> - <url>"
   - If PR check error:
     - Logs warning but continues to human_review
     - Message: "Warning: Could not check for existing PR: <error>"
   - If no existing PR:
     - Proceeds to human_review (PR creation will be handled by subtask-3-3)
     - Message: "No existing PR found for this branch."

4. State transitions after successful push:
   - Initially sets status to "creating_pr" while checking
   - If existing PR found: status → "human_review"
   - If no existing PR: status → "human_review" (ready for PR creation)
   - If error checking: status → "human_review" (graceful degradation)

Verification:
- Python syntax check: PASSED (python3 -m py_compile qa.py)
- gh pr list command format verified correct
- Expected output: Empty array [] or existing PR details [{"url": "...", "number": ..., "title": "..."}]

Implementation Notes:
- Follows the pattern: gh pr list --head <branch> --json url,number,title
- Links to existing PR instead of creating duplicates
- Graceful degradation: proceeds even if PR check fails
- existing=True flag distinguishes linked PRs from newly created ones
